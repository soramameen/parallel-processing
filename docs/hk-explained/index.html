1. グラフとは？点と線のつながり

まず、すべての基礎となるグラフについて理解しましょう。グラフとは、「点」と「線」でできたシンプルな構造です。

図1-1：簡単なグラフの例。4つの点（頂点）と5本の線（辺）でできている

基本用語

  • 頂点（vertex）：グラフ上の点。上の例では A, B, C, D の4つ
  • 辺（edge）：2つの頂点をつなぐ線。A-B、A-C、B-C、B-D、C-D の5本
  • 隣接（adjacent）：2つの頂点が辺でつながっているとき、「隣接している」という

例えば、頂点 B と頂点 C は辺でつながっているので、「B と C は隣接している」と言います。一方、A と D は線でつながっていないので、隣接していません。

直感的な理解： グラフは「関係」を表します。SNSなら人が頂点、友達関係が辺。道路網なら交差点が頂点、道路が辺。このように、現実世界の様々な「つながり」をグラフで表現できます。

次に知る必要があること： グラフの中で、「全員が全員と友達」のような特別な部分集合があります。これがクリークです。

2. クリークと極大クリーク

グラフの中で、すべての頂点が互いに隣接している部分集合をクリークといいます。

図2-1：クリークと極大クリーク。左の {B,C,D} も右の {A,B,C} もクリークだが、右だけが極大

クリークとは

クリークとは、選んだ頂点のどの2つを取っても必ず辺がある頂点の集合です。「全員が全員と友達」の状態です。

例：

  • {B, C, D} はクリーク（B-C、B-D、C-D の3本すべて辺がある）
  • {A, B, C} もクリーク（A-B、A-C、B-C の3本すべて辺がある）
  • {A, B, D} はクリークではない（A と D の間に辺がない）

極大クリークとは

極大クリークとは、もう1つも頂点を加えられないクリークのことです。つまり、「これ以上拡張できない」クリークです。

例を見てみましょう：

  • {B, C, D} はクリークですが、極大ではありません。なぜなら、頂点 A を加えても... あれ、実は A-D には辺がないので加えられませんね。では D を外して {B, C} を考えると、A を加えて {A, B, C} にできます。
  • {A, B, C} は極大クリークです。D を加えようとしても A-D に辺がないので加えられません。

なぜ「極大」が重要か： 現実の問題では、「最大の仲良しグループを全部見つけたい」ことが多いです。小さいグループは大きいグループに含まれているので、極大クリークだけを列挙すれば十分です。

応用例： タンパク質の相互作用ネットワークで極大クリークを見つけると、一緒に働くタンパク質の複合体がわかります。SNSでは、密接につながったコミュニティを発見できます。

次に知る必要があること： すべての極大クリークを見つけるには、どうやって探せばいいでしょうか？一つずつ試していくバックトラック探索という方法を見ていきます。

3. バックトラック探索：選択肢を試す

極大クリークをすべて見つけるには、頂点を1つずつ「入れる」「入れない」を試していくバックトラック探索が基本です。

図3-1：バックトラック探索の木。各節点は「今作っているクリーク」、枝は「次にどの頂点を試すか」

バックトラックの仕組み

バックトラック探索は、次のように動きます：

  1. 空集合から始める：最初は何も選んでいない状態 { } から
  2. 1つずつ試す：頂点を1つ選び、「これを加える」「加えない」の両方を試す
  3. 枝を伸ばす：各選択は木の枝のように分岐していく
  4. 行き止まりで戻る：もう加えられる頂点がなくなったら、極大クリークとして記録し、前の分岐点に戻って別の選択肢を試す

問題点： すべての頂点について「入れる」「入れない」を試すと、n 個の頂点に対して 2n 通りの組み合わせを調べることになります。頂点が30個あれば、10億通り以上！これは現実的ではありません。

次に知る必要があること： もっと賢く枝刈りをして、無駄な探索を減らす方法があります。それが Tomita の BK 法です。

4. Tomita の BK 法：ピボットで賢く枝刈り

Bron-Kerbosch アルゴリズムの改良版である Tomita の BK 法（CLIQUES）は、ピボットという頂点を選んで、探索する枝を大幅に減らします。

ピボットとは

ピボットは、「この頂点と辺がない候補頂点」が最も少ない頂点のことです。ピボットを選ぶことで、試す必要のある分岐を減らせます。

図4-1：ピボットの選択。ピボットと辺がない頂点だけを試すことで、分岐を減らす

Hk での分岐：必ず2つに

重要な点は、Hk というグラフでは、ピボットの選択によって分岐が必ず2つになるということです。

バックトラック探索では、現在構築中のクリークを Q と表します（Q = 「今まで選んだ頂点の集合」）。Hk では、Q から出発して次の頂点を追加する際、ピボットの働きで必ず2つの分岐が生まれます：

図4-2：Hk では各段階で2分岐し、k 段続くと 2k の葉ができる

普通のグラフなら、ピボットの効果で分岐は少なくなります。しかし Hk は特殊で、どのピボットを選んでも2つの分岐が必要になるように巧妙に設計されています。これを k 段繰り返すと、2k+1 − 1 回の呼び出しが発生します。

ポイント： CLIQUES は通常は効率的ですが、Hk のような「意地悪な」グラフでは、指数的な計算量を避けられません。

次に知る必要があること： では、この Hk とは一体どんなグラフなのでしょうか？なぜこのグラフが CLIQUES を困らせるのか、その構造を見ていきます。

5. Hk の登場：なぜこのグラフが必要か

CLIQUES が本当に効率的かどうかを調べるには、最悪ケースを見つける必要があります。つまり、「極大クリークは少ないのに、CLIQUESが大量の計算をしてしまう」グラフです。それが Hk です。

Output-polynomial とは

列挙アルゴリズムの効率を測る基準の1つが output-polynomial です：

Output-polynomial: 実行時間が「入力サイズ n と出力個数 m」の多項式で抑えられる。つまり、O((n + m)c) のような形。

もし CLIQUES が output-polynomial なら、極大クリークが少ないグラフでは速く終わるはずです。しかし...

Hk の反例

2k² + 9k
頂点数 n
≤ n²
極大クリーク数
≥ 2k+1 − 1
再帰呼び出し数

Hk では、n = 2k² + 9k なので k ≈ √(n/2) です。したがって再帰呼び出しは 2Ω(√n) 回になり、これは n や n² のどんな多項式よりも速く増えます。

結論： CLIQUES は output-polynomial ではありません。Hk がその証拠です。

次に知る必要があること： Hk はどのような構造で、なぜ CLIQUES を指数的な計算に追い込めるのでしょうか？その秘密は3種類の頂点にあります。

6. Hk の構造：3つの頂点タイプ

Hk は、3種類の頂点を巧妙に組み合わせて作られています。まず、具体例として最も小さい H1 を見てみましょう：

図6-0：H₁ の完全図。k=1 の最小例。ガード g₁（オレンジ）、ペア a₁・b₁（青）、証人 w₁〜w₈（緑）の3種類

この図から、3種類の頂点の役割が見えてきます。それでは、一般の Hk の構造を詳しく見ていきましょう：

guard（ガード）
pair（ペア）
witness（ウィットネス）

3つの頂点タイプ

Hk の頂点は、次の3つのグループに分かれます。ここで、U、M、W という記号を導入します：

  • U（ガードの集合）：guard 頂点 g1, …, gk をまとめた集合。U = {g1, …, gk}
  • M（ペアの集合）：すべてのペア頂点 a1, b1, …, ak, bk をまとめた集合。これらは全て互いに辺があるので、M は1つの大きなクリークです（ペアの点をまとめた集まり＝M）
  • W（証人の集合）：すべての witness 頂点をまとめた集合

これらの記号を使って、詳細を表にまとめます：

タイプ 個数 役割
guard U = {g1, …, gk} k 個 互いに辺なし（独立集合）。常にピボットになり、2分岐を生む
pair M = B1 ∪ … ∪ Bk
各 Bi = {ai, bi}		 2k 個 すべて互いに辺あり（クリーク）。2分岐の「分岐先」になる
witness W
M の各頂点に k+3 個ずつ		 2k(k+3) 個 互いに辺なし（独立集合）。他の頂点がピボットにならないよう邪魔をする

合計頂点数： n = k + 2k + 2k(k+3) = 2k² + 9k

辺の規則

Hk は「ほとんどすべての頂点対に辺がある」グラフです。辺がない組は次の4種類だけ：

  1. guard 同士：U は独立集合
  2. gi と自分のペア Bi：gi は ai, bi と辺なし
  3. witness と所有者：各 witness は、それが属する M の頂点とだけ辺なし
  4. witness 同士：W は独立集合

それ以外の頂点対はすべて辺ありです。

この構造を具体的に見るため、k = 2 の H2 の完全な図を見てみましょう：

図6-1：H₂ の構造（実際のエッジリストから生成）。M の4頂点は完全に接続されたクリーク（実線）。破線は主要な非エッジのみ表示（guard同士、guard-ペア、証人-所有者の一部）。証人同士の非エッジ190本は省略

注： H2 は26頂点あり、完全グラフなら 26×25/2 = 325 本の辺があるはずですが、非エッジ 215 本を除くと 110 本の辺になります。図では全ての辺を描くと見にくくなるため、M のクリーク構造と主要な非エッジだけを強調しています。

構造の概念図（簡略版）

上の詳細図をより抽象的に表現すると、次のようになります：

k = 2、n = 26） a₁ b₁ a₂ b₂ M（クリーク） g₁ g₂ U（独立集合） W（witness、各 M の頂点に 5 個ずつ） a₁ の witness ... b₁ の 5個 ... a₂ の 5個 ... b₂ の 5個 witness は互いに辺なし、所有者とも辺なし、他とは辺あり 辺あり 辺なし

図6-2：H₂ の概念図。辺の大部分を省略し、構造の本質を強調

各タイプの役割

guard の役割： ピボットになる。gi と辺がない候補は、他の guard k−1 個 + 自分のペア 2個 + 自分 = k+2 個。これが最小なので、常にピボットに選ばれる。分岐頂点は ai と bi の2つ。

pair の役割： 2分岐を生む。各 guard gi がピボットになると、ai と bi の2つの子呼び出しができる。どちらも同じ条件を満たすので、再帰的に2分岐が続く。

witness の役割： 邪魔をする。M の頂点 c は、自分の witness k+3 個と辺がないので、「辺がない候補」が k+3 個以上になる。これは guard の k+2 個より多いので、M の頂点はピボットに選ばれない。witness 自身も独立集合なので、witness もピボットにならない。

次に知る必要があること： この構造がどんな結果を生むか、具体的な数字で見てみましょう。

7. 対比：少ない答えと爆発する計算

Hk の驚くべき性質は、極大クリークは少ないのに、再帰呼び出しは指数的に増えることです。

極大クリークの個数

極大クリークは、次のルールで決まります：

  • guard を高々1個、witness を高々1個選ぶ
  • M の部分は、選んだ guard と witness の両方と辺がある頂点すべて

選び方：

  • guard：なし、または k 通り → k+1 通り
  • witness：なし、または 2k(k+3) 通り → 2k(k+3)+1 通り

上界： (k+1)(2k(k+3)+1) ≤ n²

実際の個数はこれより少し少ない（一部の組み合わせは極大にならない）

再帰呼び出しの個数

一方、「guided call」と呼ばれる特定の条件を満たす呼び出しは、必ず guard をピボットにして2分岐します。これが k 段続くと：

1 + 2 + 4 + 8 + … + 2k = 2k+1 − 1 回

n²) ≪ 再帰呼び出し 数は指数的 Ω(2√n) ... ...

図7-1：極大クリークは少ないが、CLIQUES は大量の再帰呼び出しをする

具体的な数字で確認

小さい k について、実際の数を計算してみましょう：

# Python スクリプトで検証（k = 1..5）
for k in range(1, 6):
    n = 2 * k**2 + 9 * k
    max_cliques_upper = (k + 1) * (2 * k * (k + 3) + 1)
    guided_calls = 2**(k + 1) - 1
    print(f"k={k}: n={n}, 極大クリーク≤{max_cliques_upper}, guided呼び出し={guided_calls}")

結論： Hk は、CLIQUES が output-polynomial でないことの具体的な証拠です。ピボットのタイブレークや分岐の処理順をどう選んでも、この指数的な計算量は避けられません。
